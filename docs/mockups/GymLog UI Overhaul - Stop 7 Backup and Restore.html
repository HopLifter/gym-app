Stop 7: backup and restore

Today, "Backup All Data" saves a file, and "Restore from Backup" asks one question and replaces all data. Nothing tells you when you last made a backup, the question does not show what is in the file, and a restore cannot be undone.

Bug found: a restore deletes every kind of data that is not in the file. A file with only History in it would delete your Queue, programs and Exercise List. D4 below fixes this.

Data model: four changes (your OK first)

Your data is 42 KB. The phone allows about 5 MB, so one extra copy is no problem.

  • D1. Backup file: a new "_meta" part with the app version, the date and time of the backup, and the counts. Old backup files have no "_meta" and still restore. Older app versions ignore "_meta", so a new file still restores in an old version.
  • D2. New key on the phone: last backup (gymapp_last_backup_v1): the date and time and the file name. It is not in the backup file, because it belongs to this phone.
  • D3. New key on the phone: the undo copy (gymapp_before_restore_v1): all your data as it was just before the last restore. There is only one copy; the next restore replaces it. "Undo Last Restore" swaps the two, so you can also undo the undo. Not in the backup file.
  • D4. A restore writes only what is in the file. Data that the file does not have stays as it is. An empty value in the file ("none at backup time", for example no program) still clears that data, as now.

Four other proposals:

  • R1. Reminder. When the last backup is more than 7 days old (or there is none) and you finished a workout since then, the message bar shows "Last backup: 12 days ago" with "Back Up" after Finish Workout. Settings shows the same line in red. No pop-up when the app opens.
  • R2. Ask the browser to protect the data (navigator.storage.persist()) once when the app opens, without a question to you. About shows the result. The browser decides; on some phones the answer is always "No".
  • R3. Two open copies of the app: when one copy saves, the other reloads. Without this, an old copy can save over new data. You see nothing in normal use.
  • R4. Limit: the app counts a backup when it makes the file. It cannot know if you saved the file or cancelled the download.

I also propose "Back Up All Data" in place of "Backup All Data" ("back up" is the action, "backup" is the file).

Decision (user, 17 Nov 2026): D1 to D4, R1 to R4 and the rename accepted. Screen 4 has a ✕ at the right edge of the message, with "Back Up" just to its left. Built in v72.
